# PM2.5 KANCHANABURI — Online Pixel Board Game

## กติกาและระบบเกม (ฉบับอัปเดต)

- เล่นออนไลน์ได้ 2–4 คน ผ่านห้องและรหัสห้อง
- ผู้เล่นทุกคนเริ่มต้นด้วยเงินสดคนละ **1,000 บาท** และชื่อเสียง **0 คะแนน**
- เกมจับเวลาการเล่นจริง **30:00 นาที** เริ่มจาก 00:00
- เมื่อทอยลูกเต๋า ผู้เล่นเดินตามผลรวมของลูกเต๋า
- เมื่อตกช่องที่ยังไม่มีเจ้าของ ระบบส่งหน้าต่างซื้อ/ไม่ซื้อให้ผู้เล่นคนนั้นหลังเดินเสร็จประมาณ 3 วินาที
- เมื่อซื้อหรือปฏิเสธการซื้อ ระบบจะเปลี่ยนตาให้อัตโนมัติ ไม่ต้องกดจบเทิร์น
- ช่องที่ไม่ต้องตัดสินใจซื้อจะเปลี่ยนตาให้อัตโนมัติ
- เมื่อซื้อพื้นที่ ค่า PM2.5 รวมของเกมจะเพิ่มตามค่ามลพิษของพื้นที่นั้น
- ค่า PM2.5 แสดงบนหน้าจอตลอดเกม

## การประชุมสิ่งแวดล้อม

- เริ่มประชุมเมื่อเวลาเล่นสะสมถึง **10:00** และ **20:00**
- ระหว่างประชุม ตัวจับเวลาเกมหยุดชั่วคราว และกลับมาเดินต่อเมื่อผู้เล่นทุกคนตอบแล้ว
- ผู้เล่นแต่ละคนเลือกได้หนึ่งครั้งต่อรอบประชุม:
  - **ยืนยัน:** ต้องมีเงินอย่างน้อย 300 บาท จ่าย 300 บาท ได้เครดิต +10 และลด PM2.5 ส่วนกลาง 10 หน่วย
  - **ปฏิเสธ:** ไม่เสียเงิน เครดิตไม่เปลี่ยน และ PM2.5 ไม่เปลี่ยน
- ค่า PM2.5 จะไม่ลดต่ำกว่า 0

## ค่ามลพิษเริ่มต้นของพื้นที่

ค่าเหล่านี้เป็นค่าตั้งต้นในโค้ดและสามารถแก้ไขได้ในฟังก์ชัน `pollutionFor()` ใน `server.js`:
- สถานที่ท่องเที่ยว/ธรรมชาติที่ซื้อได้: +2 หน่วย
- เขื่อน: +3 หน่วย
- กิจกรรมล่องแพ: +1 หน่วย
- รถไฟ/ขนส่ง: +10 หน่วย
- เหมือง: +12 หน่วย
- บ้าน (หากเพิ่มเป็นทรัพย์สิน): +3 หน่วย
- โรงงาน (หากเพิ่มเป็นทรัพย์สิน): +15 หน่วย

> หมายเหตุ: กระดานเวอร์ชันนี้ยังใช้สถานที่ท่องเที่ยวกาญจนบุรีเป็นทรัพย์สินหลัก ยังไม่มีช่องบ้านและโรงงานแยกเป็นประเภทเฉพาะ ค่าบ้าน/โรงงานจึงเป็นค่าเตรียมไว้สำหรับการเพิ่มประเภททรัพย์สินภายหลัง

## เงื่อนไขแพ้–ชนะ

- เมื่อเวลาการเล่นสะสมครบ **30:00 นาที** เกมจะจบ
- ผู้ที่มี **เงินสดคงเหลือมากที่สุด** เป็นผู้ชนะ
- มูลค่าทรัพย์สินและคะแนนเครดิตแสดงในสรุปผล แต่ **ไม่นำมาคำนวณผู้ชนะ**
- หากเงินสดสูงสุดเท่ากัน ผู้เล่นที่มีเงินเท่ากันเป็นผู้ชนะร่วม

## การติดตั้งและ Deploy

1. ติดตั้ง Node.js 18 ขึ้นไป
2. เปิดโฟลเดอร์นี้แล้วรัน `npm install`
3. รัน `npm start`
4. เปิด `http://localhost:3000`
5. บน Render ใช้ Build Command: `npm install` และ Start Command: `npm start`

## ไฟล์ภาพ

- พื้นหลังจังหวัดกาญจนบุรีอยู่ที่ `background-kanchanaburi.png`
- ภาพตัวละครชาย/หญิง 4 สีอยู่ใน `assets/`
- ชื่อไฟล์ใน `assets/` ต้องตรงกับที่หน้าเว็บเรียกใช้

## หมายเหตุการทดสอบ

แพ็กเกจนี้ปรับโครงสร้างกติกาฝั่งเซิร์ฟเวอร์ให้เป็นผู้ควบคุมเงิน PM2.5 การประชุม เวลา และผลแพ้ชนะ ตรวจสอบไวยากรณ์ JavaScript และความสมบูรณ์ของ ZIP แล้ว แต่ควรทดสอบเกมหลายเบราว์เซอร์/หลายเครื่องก่อนเปิดเล่นจริง


## อัปเดตเพิ่มเติม (รอบล่าสุด)
- ผู้เล่นตกพื้นที่ที่มีเจ้าของคนอื่น จ่ายค่าเสียหาย 50% ของราคาพื้นที่ให้เจ้าของ
- เงินเริ่มต้นคนละ 1,000 บาท
- เปลี่ยนค่าชื่อเสียงเป็นเครดิต เริ่มต้น 0 เครดิต; การยืนยันประชุมได้รับ +10 เครดิต
- กระดานช่องเป็นสีขาว และพื้นที่ที่มีเจ้าของแสดงกรอบสีประจำตัวเจ้าของ
- เพิ่มเสียงเอฟเฟกต์ขณะทอยลูกเต๋า
- เมื่อเจ้าของห้องเริ่มเกม ทุกคนเห็นนับถอยหลัง 3–2–1 และเสียงประกอบก่อนเริ่ม
- ขยายตัวอักษรชื่อช่องและราคาให้ใหญ่ขึ้น


## อัปเดตหน้าตาและเสียง (รอบล่าสุด)
- เพิ่มปุ่มเริ่มเกมของเจ้าของห้องบนแถบด้านขวาบน และคงปุ่มเริ่มเกมกลางกระดานไว้
- แสดงรหัสห้องอย่างเด่นชัดมุมขวาบนหลังเข้าห้อง
- ปรับลูกเต๋าเป็นลูกเต๋าสีขาวทรงมน มีจุดสีดำแบบภาพอ้างอิง
- เปลี่ยนดนตรีเป็นจังหวะสนุกขึ้นด้วยเสียงสังเคราะห์เลียนแบบกลอง เบส มาริมบา และคอร์ดประสาน
- เพลงเริ่มเมื่อผู้เล่นกดปุ่มเพลง เพื่อให้เบราว์เซอร์อนุญาตการเล่นเสียง


## แก้ไขลูกเต๋าและนับถอยหลัง (รอบล่าสุด)
- เพิ่มการเก็บแต้มลูกเต๋าที่ได้รับจากเซิร์ฟเวอร์ไว้บนหน้าจอ ไม่ถูกล้างเมื่อเปลี่ยนเทิร์น
- ระหว่างทอย/เดิน ลูกเต๋าหมุนต่อเนื่อง และหยุดแสดงหน้าจุดตามแต้มจริงเมื่อจบแอนิเมชัน
- เพิ่มฟังก์ชันเสียงทอยและเสียงนับถอยหลังที่ถูกเรียกใช้งานจริง
- เมื่อเซิร์ฟเวอร์เริ่มนับถอยหลัง ส่งสัญญาณให้ทุกหน้าจอแสดง 3, 2, 1 และข้อความเริ่มเกม พร้อมเสียง


## อัปเดตกติกาการซื้อและการประชุม (รอบล่าสุด)
- เมื่อผู้เล่นตกพื้นที่ที่ยังไม่มีเจ้าของ จะเห็นหน้าต่างซื้อ/ไม่ซื้อเหมือนเดิม แม้เงินไม่พอ
- หากกดซื้อแต่เงินไม่พอ จะแสดงข้อความ "เงินของท่านไม่เพียงพอ" และรอให้ผู้เล่นกดตกลงก่อนเปลี่ยนตา
- เมื่อซื้อที่ดินสำเร็จ มีเสียงเอฟเฟกต์เหรียญ/กระดิ่ง
- ตัวจับเวลาเดินต่อเนื่องตามเวลาจริง แม้ระหว่างประชุม
- การประชุมถูกเรียกเมื่อ PM2.5 สะสมถึง 100, 200 และ 300 หน่วย (สูงสุด 3 รอบ) แทนการเรียกตามนาทีที่ 10 และ 20
- การเปลี่ยนตาหลังข้อเสนอซื้อ จะเกิดเมื่อผู้เล่นซื้อสำเร็จ, ปฏิเสธ, หรือยืนยันข้อความซื้อไม่สำเร็จแล้วเท่านั้น


## แก้ไขระบบเทิร์นและเจ้าของพื้นที่ (รอบล่าสุด)
- เซิร์ฟเวอร์จะล็อกเทิร์นระหว่างผู้เล่นเดินตามลูกเต๋า และรอ event `movementComplete` จากผู้เล่นที่ทอยก่อนจึงดำเนินขั้นตอนต่อไป
- หากเดินถึงพื้นที่ซื้อได้ จะส่งหน้าต่างซื้อหลังจบแอนิเมชันการเดินเท่านั้น
- หากไม่ต้องซื้อ จะเปลี่ยนตาหลังจบแอนิเมชัน ไม่เปลี่ยนตาก่อนผู้เล่นเดินเสร็จ
- เพิ่ม watchdog 10 วินาทีในเซิร์ฟเวอร์ เพื่อปลดล็อกเทิร์นหากเบราว์เซอร์ไม่ส่งการยืนยันจบแอนิเมชัน
- ผู้เล่นไม่สามารถทอยซ้ำระหว่างกำลังเดินหรือมีข้อเสนอซื้อค้างอยู่
- พื้นที่ที่ซื้อแล้วมีกรอบสีและพื้นหลังโปร่งสีประจำเจ้าของ พร้อมป้ายชื่อเจ้าของ


## แก้ไขบั๊กหน้าต่างซื้อพื้นที่ไม่แสดง (รอบล่าสุด)
- แก้ต้นเหตุใน `land()`: เดิมเซิร์ฟเวอร์ส่ง `purchaseOffer` ทันทีตั้งแต่ก่อนแอนิเมชันเดินเสร็จ และส่งซ้ำจาก `completeMovement()` โดยข้อมูลรอบที่สองไม่มีชื่อ/ราคา ทำให้หน้าต่างอาจไม่แสดงหรือข้อมูลผิด
- เปลี่ยนให้ `land()` เก็บข้อมูลข้อเสนอซื้อไว้ใน `pending` อย่างเดียว
- เมื่อผู้เล่นเดินเสร็จและส่ง `movementComplete` แล้วเท่านั้น เซิร์ฟเวอร์จึงส่ง `purchaseOffer` ที่มีชื่อ ราคา และค่า PM2.5 ครบ
- ฝั่งหน้าเว็บแสดงหน้าต่างภายใน 0.35 วินาที และป้องกัน event ข้อเสนอซ้ำ
- ยังคงรอผู้เล่นกดซื้อหรือไม่ซื้อก่อนเปลี่ยนเทิร์น
